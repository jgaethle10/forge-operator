# Evercraft Week in Motion Machine

Week in Motion is a standing Systemia publication machine. It is not a weekly blank-page writing task.

## Canonical weekly cycle

1. Freeze the previous completed Monday through Sunday window in America/Los_Angeles.
2. Collect repository events, merged pull requests and workflow outcomes from the canonical Forge estate.
3. Normalize every item into an evidence record with a source locator, timestamp, truth state and portfolio theme.
4. Send the frozen packet to a replaceable Evercraft editorial model endpoint.
5. Require the model to return a deep Journal edition, substantive social master, listen-along comment, Fallen visual brief and out-of-band claim-to-evidence mapping.
6. Run the publishing doctrine as code. The gate rejects forbidden dash characters, thin articles, stacked short one-sentence paragraphs, low paragraph density, unsupported evidence references and unsupported numeric tokens.
7. Publish only through the existing Systemia Journal ingress contract. The Journal ingress performs its own evidence, editorial, visual and live-render gates before issuing public-release receipts.
8. Preserve the evidence ledger, editorial package, quality report, publication payload, publication result and Fallen visual brief as a weekly artifact.
9. If any gate fails, stop. A blocked Week in Motion is preferable to a polished false one.

## Editorial benchmark

The canonical benchmark is the Sep 14-20, 2026 Week in Motion. Its defining traits are company-level thesis, long developed paragraphs, evidence woven into narrative, explicit truth states, failures included as learning, no vanity metrics, no one-line AI cadence and a closing synthesis about what the week taught Evercraft how to do next.

## Provider ownership

The machine owns the process. The language model does not.

The editorial provider is configured through an OpenAI-compatible endpoint so Evercraft can point the machine at a sovereign model, a hosted model or another approved capability without rewriting the weekly system. The provider receives a bounded evidence packet and cannot publish directly.

Required runtime configuration:

- EVERCRAFT_EDITORIAL_ENDPOINT
- EVERCRAFT_EDITORIAL_TOKEN when the endpoint requires one
- EVERCRAFT_EDITORIAL_MODEL
- SYSTEMIA_JOURNAL_INGRESS_URL
- SYSTEMIA_JOURNAL_SHARED_SECRET

The Journal already exposes the authenticated Systemia ingress and its article page already includes the Listen to this report reader. The weekly machine therefore does not need to invent another publication path.

## Schedule

The GitHub resident wake runs every Monday at 15:30 UTC. The process itself uses America/Los_Angeles for the editorial week boundary. Manual runs are available through workflow_dispatch.

## Evidence boundary

GitHub is one collector, not the final universe of Evercraft evidence. Additional collectors should implement the same evidence-record shape for Systemia mission receipts, Drive artifacts, Journal publication receipts, Evercraft Clip distribution receipts, field work, commerce and other owned systems. Missing collectors are a coverage limitation, never permission to infer that unobserved work did not happen.
