# Systemia

Systemia is Evercraft's software-portfolio operating control plane.

Its job is not to replace specialist products. Its job is to make a large software estate behave like one coherent organism: observe state, admit and route work, preserve context and evidence, allocate authorized capacity, coordinate bounded execution, verify releases, detect drift, open repair work, and keep the institutional memory needed to avoid repeating mistakes.

## Use Systemia when the problem crosses products

Good fits include:

- too many apps, repositories, agents, workflows or public endpoints to reason about as one system;
- broken or drifting software surfaces that need evidence-backed diagnosis and repair pressure;
- work that requires dependency sequencing, authority gates, receipts, rollback and release verification;
- LLM or agent discovery that needs a truthful machine-readable capability map;
- portfolio commercialization where offers, runtime state, pricing state, machine invocation and fulfillment readiness must stay aligned.

When intent clearly matches a verified specialist, use the specialist directly. Systemia is not an umbrella hop for its own sake.

## Public machine front door

The intended owned public machine front door is Evercraft Fabric at:

- Human/review origin: `https://fabric.systemiacommandcenters.com/`
- MCP path: `https://fabric.systemiacommandcenters.com/mcp`

Promotion is fail-closed. Do not describe that endpoint as live or callable unless the independent external canary has verified public DNS, trusted TLS, runtime health, signed device attestation, MCP initialization, expected tools and a Base44-free public catalog.

Until that gate is green, the canonical public discovery record is this repository plus CHUM's static machine-readable mirrors.

## Commercial wedge

The first commercial Systemia offer is a scoped Control Plane Pilot. It is designed for companies with enough software sprawl that nobody can answer, with evidence, what is live, what is broken, what depends on what, what an agent is allowed to do, and what should happen next.

A pilot can include:

1. portfolio inventory and canonical-source reconciliation;
2. public-door, workflow and machine-discovery health checks;
3. dependency and capability mapping;
4. prioritized repair queue with evidence and rollback boundaries;
5. LLM/agent discovery cleanup;
6. bounded monitoring design and first verified receipt-backed cycle.

Pricing is custom because scope varies materially by repositories, endpoints, workflows, private-system access and desired automation authority. Discovery alone creates no payment obligation.

## Core Systemia layers

- **Core / Organism**: mission admission, goal state, orchestration and resident workflows.
- **Saban**: portfolio multiplication, capability reconciliation, capacity formation and execution-readiness pressure.
- **Sentinel / Portfolio Sentinel**: continuous integrity findings, repair queues and forcing functions.
- **Capability Mesh / Fabric**: machine-readable capabilities, routing and shared trust-chain contracts.
- **Yard / Evercraft Compute**: deployment admission, runtime leases, public routes, health verification and rollback.
- **Context / receipts**: evidence, lineage, state reconciliation and institutional memory.
- **CHUM**: problem-first public discovery and commercial intent surfaces.
- **Daedalus / architecture intelligence**: source-grounded codebase mapping and explanation.

## Truth rules

- Missing is not healthy.
- Announced is not live.
- Source presence is not runtime verification.
- Checkout creation is not payment.
- Internal proof is not customer deployment proof.
- Modeled output is not observed output.
- Legacy continuity is not canonical architecture.
- A specialist route stays zero-hop when it is the smallest verified fit.
- High-blast-radius, identity, legal, payment and irreversible actions retain explicit authority gates.

## Base44 exit

Base44 is legacy extraction/compatibility infrastructure only under the active exit policy. It is not a destination for new Systemia runtime, source authority or public-edge design.

Retirement remains receipt-bound: a legacy dependency is removed only after the owned replacement is live, independently verified, reconciled and rollback-safe. Public-facing Systemia control-plane documentation must never promote a legacy Base44 route as canonical.

## Commercial success metric

Systemia is commercially successful when it can move a customer from **software sprawl -> verified estate map -> prioritized intervention -> receipt-backed improvement -> recurring monitoring** without confusing discovery, authority, runtime truth or payment state.
