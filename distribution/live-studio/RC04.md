# Evercraft LIVE Studio RC04: Public Release Gateway

**State:** implementation candidate on feature/evercraft-live-public-gate-rc04; no publication, TikTok transport, production release, or canonical Systemia mission admission implied.

RC03 (PR #1242) runs local illustrative worlds. RC04 adds a deliberately separate path for **actual recorded work**. The signed release gateway, publisher and read-only stage must all pass before a real artifact can be displayed. The public stage defaults to HOLD.

## Flow
1. A real output is completed and independently QA'd under its existing Systemia mission.
2. An authorized human editor performs rights, evidence, safety and privacy review. Approval happens **outside the public stage**.
3. The editor signs an evercraft.live.signed-release.v1 envelope using a privately held Ed25519 signing key. The corresponding public key goes to the release builder; **never commit private keys**.
4. The media is staged in an explicitly public-only directory with SHA-256 content-addressed filename: media/<sha256>.png (or jpg, jpeg, webp, mp4, webm). This is a **curated copy**, not a private Drive URL.
5. The local publisher verifies signature, state, rights, no-minor/no-personal-data declarations, approval window, revocation list, file type signature, and complete media bytes digest. It emits only a minimized public-feed.json under the public root.
6. public-stage.html on the **same trusted origin** renders the approved **recording**. A missing, invalid, revoked or stale release results in a neutral HOLD slate.
7. Existing RC03 producer/scene director remains separate. No TikTok stream is started by any tool here.

## Commands (Node 22, no package dependencies)

    node --test distribution/live-studio/test/*.test.mjs
    node distribution/live-studio/publish-public-feed.mjs /private/signed-envelope.json /private/reviewer-public.pem /path/to/public-root /private/revoked-receipts.json

The public root must already contain the approved content-addressed media. The revocation file is a JSON array of revoked receipt IDs, including [] when empty. Missing or malformed revocation data prevents publication. The producer must run on each new approval/revocation and periodically to retire stale releases. A failed run overwrites a previously READY feed with HOLD.

To preview the public stage locally:

    cp distribution/live-studio/public-stage.html /path/to/public-root/index.html
    python3 -m http.server 8080 --directory /path/to/public-root

Use localhost only for development, review and physical-device testing; public serving additionally requires HTTPS, restricted write authority, no-store headers on public-feed.json, actual browser media QA, and controlled operations.

## Signed payload example (illustrative values, NOT an authorization)
Signature is base64(Ed25519.sign(UTF8(canonical(payload)))), with object keys recursively sorted as implemented by canonical() in release-gate.mjs. The editor must inspect and sign the exact final payload.

    {
      "schema": "evercraft.live.signed-release.v1",
      "payload": {
        "receipt_id": "live-approval-example-001",
        "mission_key": "private-source-mission-key",
        "release_state": "approved",
        "release_type": "recorded_media",
        "rights_state": "cleared",
        "sensitivity": "public",
        "minor_present": false,
        "person_data": "none",
        "source_state": "reviewed",
        "title": "Public-reviewed construction recording",
        "caption": "A documented internal engineering prototype; not a field deployment.",
        "media_path": "media/<actual-64-character-sha256>.mp4",
        "media_mime": "video/mp4",
        "media_sha256": "<actual-64-character-sha256>",
        "duration_seconds": 35,
        "approval": {"reviewer_id": "approved-human-reviewer", "approved_at": "2026-10-14T20:00:00.000Z"},
        "expires_at": "2026-10-15T20:00:00.000Z"
      },
      "signature": "<Ed25519 signature over canonical payload>"
    }

Additional private source evidence may be kept inside the signed payload, but **never** appears in the public feed. No real private mission data belongs in committed examples. The public feed is a generated output, not a GitHub-tracked artifact.

## Fail-closed behavior and limitations
- No valid signature, public key, clearance or media digest: **HOLD**.
- Missing/expired/future-dated approval or approval longer than 7 days: **HOLD**.
- Explicit revocation: **HOLD on next publisher run**; the viewing client also checks the feed every 45 seconds and refuses feeds older than 15 minutes.
- Privacy clearance is a *reviewer assertion*, not an AI guarantee that footage is free of sensitive content. Manual inspection remains mandatory.
- File magic verification does not guarantee successful decoding or legal ownership. Preview and rights review are separate required gates.
- Browser client trusts the publisher on the same origin; if that origin is compromised, a static feed itself is not cryptographically verified on the client. Harden hosting and access controls.
- This is a **public recorded-artifact stage**, not a live agent feed, continuous broadcast server, RTMP encoder, TikTok integration, or unattended livestream authorization.
