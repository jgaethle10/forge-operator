## One clock, real receipts

`systemia/organism/kaidance-company-heartbeat-runner.mjs` invokes `runLearningCommunityCycle` once for each newly admitted five-minute company tick. Same-tick reruns return duplicate without claiming new advancement.

The per-product ledger records the exact source fingerprint, known source files, latest bounded test receipt and unmet development/release gate. **No more than two** approved Node test groups run during one heartbeat. Proof is due only after source change, missing/failed proof, or expiry (one hour). Durable local state prevents a repeated unchanged passing test from being recorded as progress. Workloads not yet implemented have an explicit review/recovery queue, not fake green tests.

All workstream state stays under the same company output directory:
`<company-heartbeat-out>/learning-community/{state,latest,queue}.json`. The company-wide queue includes the exact development work key, verified source fingerprint, one next action and required approval. It grants **zero execution, code-generation, publishing, payment, contact or child/member-data authority.** Source canaries and the review queue are real bounded engineering work; they do not automatically write product code.

CI's existing `.github/workflows/kaidance-frontier-field.yml` five-minute best-effort schedule now calls the company runner with `--prove-learning`, executes focused tests, caches the new durable state and uploads receipts. The GitHub schedule may delay or skip runs. It is **not** proof of a continuously running owned Systemia resident every 300 seconds.

An existing owned Systemia resident may opt in with `SYSTEMIA_KAIDANCE_LEARNING_SOURCE_PROOFS=true`; only after an authorized deployment, durable private state, matching source ref and two independently observed cycles should it be called live. This work does **not** redeploy any physical machine or alter Kaidance's service binding.
