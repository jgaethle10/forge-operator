Broken checkout: diagnose the revenue leak before rebuilding

If customers cannot pay, begin with the exact purchase path rather than a whole-site redesign. Reproduce the failure across the relevant device and browser context, record the visible step that fails, and separate customer-visible evidence from private root-cause hypotheses.

Check the boundaries

Payment providers, authentication, inventory, taxes, redirects, webhooks, browser errors, and application state can all affect checkout. Public observation can identify the failing experience, but private logs, credentials, provider dashboards, and code require explicit authorization.

Repair the smallest responsible layer

If a bounded repair restores the purchase path safely, that can be more rational than replacing a working system around one failure.
