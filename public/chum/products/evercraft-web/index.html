Authority and boundaries

public discovery and live-verified read-only public URL fetch through the neutral Evercraft Web MCP; search and browser automation remain separately held/gated

  • public Fetch is live-verified by external MCP initialize, tools/list, successful public-page fetch, and private-target rejection canaries
  • Evercraft Search remains held until independently verified
  • browser automation remains behind Systemia runtime and authorization gates and is not represented as live through the public MCP
  • authenticated browsing requires explicit authorized profile state and credential isolation
  • public discovery does not expose private Systemia topology or credentials
  • payment does not expand permissions

Discovery and matching create no payment obligation. Human confirmation remains required where the product declares it, and checkout creation is not proof of payment.
